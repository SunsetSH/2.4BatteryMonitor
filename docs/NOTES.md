# Заметки

Неочевидное, на чём уже спотыкались. Пункт на 1–3 строки: что, где, почему.

## Сборка и окружение

- `make` из Git Bash падает с `Cannot create temporary file in C:\WINDOWS\`: Git Bash и MSYS2 make делят окружение
  неправильно. Запускать из PowerShell с `C:\msys64\mingw64\bin;C:\msys64\usr\bin` в начале `PATH`.
- `build/version.h` генерирует `scripts/generate-version.ps1` при каждой сборке. Не редактировать, версия берётся из
  `VERSION` / аргумента `build.bat`.
- Запущенное приложение держит `2.4BatteryMonitor.exe`, и `make` падает на линковке с `Permission denied`.
  Владелец обычно держит его открытым: `--quit` закрывает его монитор, поэтому сначала спросить.
- `make` собирает параллельно (`-j` по числу ядер). Один тест: `make build/tests/<имя>.exe`, затем
  `./build/tests/<имя>.exe` из корня (тесты `lang_test` и `driver_lanes_test` читают исходники по относительным путям).
- Тест драйвера линкуется с одним `.cpp` и подменяет `HidDev`. Новые тесты берут общую `tests/fake_hid.h` и линкуют
  `src/hid_util.cpp`; старые со своей заглушкой при новом методе `HidDev` надо дополнить (так сломался `dareu_driver_test`).
- `2.4BatteryMonitor.exe` собран как GUI: PowerShell не ждёт его и не показывает вывод `--list` / `--json`, если
  не перенаправить его (`| Out-String`).
- В PowerShell `[Win32]::FindWindow("класс", $null)` передаёт пустую строку, а не NULL, и окно не находится;
  вызывать FindWindow из C#-обёртки с `null` внутри.
- Inno Setup 6 стоит для пользователя: `%LOCALAPPDATA%\Programs\Inno Setup 6\ISCC.exe` (его ищет
  `build-installer.ps1`). Скрипт заново упаковывает ZIP, и хеш меняется: чтобы добавить установщик к уже
  опубликованному релизу, вызывать ISCC напрямую, затем `sign-update.ps1`.
- `arbiter_driver_test` требует и `lamzu.cpp`: тест проверяет, что Arbiter и LAMZU на общем VID `373E` не
  перехватывают устройства друг друга.

## Драйверы

- Порядок вызовов в `src/devices.cpp#PollAllDevices` значим: первый драйвер забирает `VID:PID`. Новый драйвер на
  общем VID ставится до того, кто тоже сканирует этот VID (комментарии в коде говорят, до кого).
- Драйверы производителей из `src/driver_lanes.h` работают в своих потоках и видят только коллекции своего VID.
  Новый драйвер на таком VID входит в полосу, иначе падает `driver_lanes_test` (ADR 0007).
- Уровни наушников идут в `DeviceStatus::left / right / casePct`, а не в `detail` и не в `via` (раньше AirPods
  писали их в `via`, и подключение не переводилось).
- Ключ устройства (`DeviceStatus::key`) не должен содержать путь HID: путь меняется при смене USB-порта, а по
  ключу хранятся имя, порог уведомлений и история. Для одинаковых устройств `PollContext::StableKey`.
- `IgnoreDevices` действует в трёх местах: HID-коллекции убираются до драйверов, `PollBluetooth` пропускает их
  контейнеры (`PollContext::ignoredPaths`), `DropIgnored` чистит итог от источников без HID (XInput, BLE-рекламы).

## Тексты и документация

- PowerShell 5.1: `Get-Content -Raw` читает UTF-8 без BOM как ANSI, а `Set-Content -Encoding utf8` пишет с BOM;
  так однажды испортилась кириллица в PLAN.md. Править тексты через `[IO.File]::ReadAllText` / `WriteAllText` с
  `UTF8Encoding($false)` или инструментами редактора.
- README для посетителей на трёх языках (русский основной); карта проекта и выпуск релиза в `docs/DEVELOPERS.md`.

- Каждая фраза `T(L"...")` должна быть в `lang/_template.txt`, иначе падает `lang_test`. Фразы, переданные в функцию
  переменной (`Switch(api, L"...")` в `settings_rows.cpp`), тест не видит: добавлять вручную.
- Исходный язык строк английский: ключ перевода это сама английская фраза в `T(L"...")`. Изменение английской фразы
  отвязывает все переводы, их надо перенести в `lang/*.txt`.
- В старом README таблица устройств содержала дубли с противоречиями. Для 8BitDo старая строка говорила, что в режиме
  X-input донгл не отдаёт уровень, новая и код (`eightbitdo.cpp`) читают его через канал `FF7A`. Оставлена версия кода.
- Таблица устройств одна, на английском, в `docs/DEVICES.md`: модели и `VID:PID` должны совпадать с выводом `--dump`.
